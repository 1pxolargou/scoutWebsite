## 1. Με μια ματιά

|             |                                                                                           |
| ----------- | ----------------------------------------------------------------------------------------- |
| Framework   | **Next.js 16** (App Router) + **React 19** + **TypeScript** (strict)                      |
| Styling     | **Tailwind CSS v4**: τα χρώματα και οι γραμματοσειρές ορίζονται στο `src/app/globals.css` |
| Περιεχόμενο | Αρχεία **MDX/JSON** μέσα στο `content/`, επικυρωμένα με **zod** κατά το build             |
| Νέα         | Από τη σελίδα **Facebook** (Graph API), με ενδεικτικά δεδομένα όταν δεν υπάρχει token     |
| Εγγραφές    | Μόνο μέσω της υπάρχουσας **Google Form**, χωρίς δική μας φόρμα                            |
| Χάρτες      | **Leaflet** + πλακίδια OpenStreetMap, που φορτώνουν μόνο με κλικ                          |
| Έξοδος      | **Στατικό site** (φάκελος `out/`): δεν χρειάζεται server ή βάση δεδομένων                 |

Όλο το κείμενο που βλέπει ο επισκέπτης είναι στα ελληνικά.

> **Σημαντικό για την έκδοση του Next.js:** η έκδοση 16 έχει αλλαγές σε σχέση με παλαιότερες.
> Πριν αλλάξετε κάτι στο routing, στο caching ή στο config, διαβάστε την τεκμηρίωση που έρχεται
> μαζί με το πακέτο, στο `node_modules/next/dist/docs/`. Δείτε και το `AGENTS.md`.

## 2. Εγκατάσταση και εκτέλεση

### 2.1 Προαπαιτούμενα

- **Node.js 20.9 ή νεότερο.** Συνιστάται η τελευταία LTS. Το npm έρχεται μαζί.
- **Git** (προαιρετικό, για ιστορικό αλλαγών).
- **Σύνδεση στο internet** στο πρώτο `npm install` και σε κάθε `npm run build`. Το build κατεβάζει
  τις γραμματοσειρές Google και τις ενσωματώνει στο site.
- Επεξεργαστής κειμένου. Προτείνεται το **VS Code** με τα extensions _ESLint_, _Prettier_,
  _Tailwind CSS IntelliSense_ και _MDX_.

#### Windows

Εγκατάσταση του Node.js με το installer από το https://nodejs.org (LTS) ή από PowerShell:

```powershell
winget install OpenJS.NodeJS.LTS
```

```powershell
winget install Git.Git
```

Κλείστε και ξανανοίξτε το τερματικό, και ελέγξτε τις εκδόσεις:

```powershell
node -v
```

```powershell
npm -v
```

Όλες οι εντολές `npm run …` του οδηγού δουλεύουν ίδια σε **PowerShell**, **cmd** και **Git Bash**.

#### Linux (Ubuntu/Debian και παρόμοια)

Προτείνεται το **nvm**, ώστε να μη χρειάζεται `sudo`:

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
```

Ανοίξτε νέο τερματικό και εγκαταστήστε τη LTS έκδοση:

```bash
nvm install --lts
```

```bash
node -v
```

Εναλλακτικά υπάρχουν πακέτα της διανομής ή το NodeSource. Βεβαιωθείτε μόνο ότι η έκδοση είναι ≥ 20.9.

### 2.2 Πρώτη εγκατάσταση

Από τον φάκελο του project:

```bash
npm install
```

Το όνομα του φακέλου (`σαιτ`) έχει ελληνικούς χαρακτήρες. Δουλεύει κανονικά και σε Windows και σε
Linux. Αν κάποιο εργαλείο σας δημιουργήσει πρόβλημα, μετονομάστε τον σε λατινικούς χαρακτήρες
(π.χ. `proskopoi-site`). Τίποτα στον κώδικα δεν εξαρτάται από το όνομα του φακέλου.

### 2.3 Ρυθμίσεις περιβάλλοντος (προαιρετικό)

Χωρίς ρυθμίσεις το site τρέχει κανονικά, με ενδεικτικά νέα. Για πραγματικά νέα από το Facebook:

**Linux / Git Bash:**

```bash
cp .env.example .env.local
```

**Windows PowerShell:**

```powershell
Copy-Item .env.example .env.local
```

Μετά συμπληρώστε τα `FB_PAGE_ID` και `FB_PAGE_ACCESS_TOKEN` στο `.env.local` (βλ. [§5.4](#54-νέα-facebook)).
Το `.env.local` **δεν μπαίνει ποτέ στο git**.

## 4. Πώς λειτουργεί

### 4.1 Στατικό site

Το `next.config.ts` έχει `output: "export"`. Στο `npm run build` κάθε σελίδα παράγεται **μία
φορά** ως HTML στον φάκελο `out/`. Αυτό σημαίνει:

- Οποιαδήποτε αλλαγή στο περιεχόμενο φαίνεται **μόνο μετά από νέο build**.
- Οι εκδηλώσεις χωρίζονται σε «επερχόμενες» και «παλαιότερες» **τη στιγμή του build**. Ξαναχτίστε
  το site όταν περάσει μια εκδήλωση.
- Τα νέα του Facebook διαβάζονται **στο build**, και το token δεν φτάνει ποτέ στον browser.
- Οι εικόνες σερβίρονται όπως είναι (`images.unoptimized`). Γι' αυτό πρέπει να είναι ήδη σε
  λογικό μέγεθος (βλ. [§5.2](#52-φωτογραφίες)).
- Μετά το `next build` τρέχει αυτόματα το `scripts/postexport.mjs`. Φτιάχνει αντίγραφα των αρχείων
  προφόρτωσης με τα ονόματα που ζητά ο browser, ώστε η γρήγορη πλοήγηση να δουλεύει σε κάθε
  στατικό hosting. Μην το αφαιρέσετε.

### 4.2 Περιεχόμενο και επικύρωση

Κάθε αρχείο του `content/` διαβάζεται από το `src/lib/content/load.ts` και ελέγχεται με τους
κανόνες του `src/lib/content/schemas.ts`. Αν κάτι λείπει ή είναι λάθος, **το build σταματά** με
μήνυμα όπως:

```
Error: Μη έγκυρο περιεχόμενο στο content/albums/2026-ekdromi.mdx
  • photos.2.allowPublish: Λείπει το allowPublish (true/false)
```

Το μήνυμα δείχνει το αρχείο και το πεδίο. Διορθώστε το και ξανατρέξτε.

### 4.3 Server και client components

Οι σελίδες είναι **Server Components** και τρέχουν μόνο στο build. Όσα χρειάζονται αλληλεπίδραση
στον browser βρίσκονται στο `src/components/interactive/` και ξεκινούν με `"use client"`:
carousel, lightbox, χάρτης, φόρμα επικοινωνίας, popup Βαθμοφόρου, κουμπί αντιγραφής IBAN, μενού
κινητού.

Κανόνας: **μην** χρησιμοποιείτε `fs`, `process.env` ή τους loaders μέσα σε client component. Τα
δεδομένα φορτώνονται στη σελίδα και περνούν ως props.

### 4.4 Τρίτες υπηρεσίες: μόνο με κλικ

Χάρτες (OpenStreetMap), η ενσωματωμένη Google Form και ο χάρτης του αρχείου φορτώνουν **μόνο όταν
ο επισκέπτης πατήσει κουμπί**. Για ενσωματώσεις τύπου iframe χρησιμοποιήστε το
`components/interactive/LoadOnClick.tsx`. Δεν υπάρχουν scripts παρακολούθησης.

### 5.2 Φωτογραφίες

1. **Ετοιμάστε την εικόνα:** JPG, πλάτος έως **1600px**, ιδανικά κάτω από **400 KB**. Δωρεάν
   εργαλεία: https://squoosh.app (στον browser), IrfanView (Windows), GIMP (Windows/Linux).
2. Αποθηκεύστε τη στο `public/images/<φάκελος>/`, με λατινικά πεζά και παύλες στο όνομα, π.χ.
   `public/images/albums/2026-parnitha/1.jpg`.
3. Αναφερθείτε σε αυτήν **χωρίς το `public`**: `/images/albums/2026-parnitha/1.jpg`.

Κάθε φωτογραφία στο περιεχόμενο δηλώνεται έτσι:

```yaml
- src: /images/albums/2026-parnitha/1.jpg
  alt: Λυκόπουλα πεζοπορούν στο δάσος # υποχρεωτικό, ΧΩΡΙΣ ονόματα παιδιών
  caption: Η πρώτη ανάβαση # προαιρετικό
  allowPublish: true # υποχρεωτικό (βλ. §8)
```

- `allowPublish: false` → η φωτογραφία **δεν εμφανίζεται**, και το build το αναφέρει ως
  προειδοποίηση.
- Χωρίς `allowPublish` ή χωρίς `alt` → **το build αποτυγχάνει**.

**Αφαίρεση φωτογραφίας:** σβήστε την εγγραφή από το αρχείο περιεχομένου και μετά το αρχείο από το
`public/images/`. Πριν σβήσετε το αρχείο, βεβαιωθείτε ότι δεν χρησιμοποιείται αλλού. Αναζήτηση
σε όλο το project για το όνομά του:

```bash
grep -rn "parnitha/1.jpg" content src
```

```powershell
Get-ChildItem content,src -Recurse -File | Select-String "parnitha/1.jpg"
```

### 5.3 Εκδηλώσεις

**Προσθήκη:** αντιγράψτε το `content/_templates/event.mdx` στο `content/events/` με όνομα
`ΕΕΕΕ-ΜΜ-ΗΗ-σύντομος-τίτλος.mdx` (λατινικά). Το όνομα αρχείου γίνεται το URL.

```mdx
---
title: Μονοήμερη εκδρομή Αγέλης στην Πάρνηθα
start: 2026-11-08T09:00 # ώρα Ελλάδας
end: 2026-11-08T16:00 # προαιρετικό
location: Πάρνηθα, Μπάφι
sections: [agelh-lykopoulon] # systima | agelh-lykopoulon | omada-proskopon | koinotita-anixneuton
summary: Μία-δύο προτάσεις για τις κάρτες (έως 220 χαρακτήρες).
cover: # προαιρετικό
  src: /images/agelh/agelh-1.jpg
  alt: Λυκόπουλα σε ορειβατικό καταφύγιο
  allowPublish: true
---

Εδώ η περιγραφή, σε Markdown: **έντονα**, λίστες, σύνδεσμοι.
```

- Ολοήμερες ή πολυήμερες: `start: 2026-07-10`, `end: 2026-07-19`, `allDay: true`.
- Προαιρετικά `mapUrl:` για συγκεκριμένο σύνδεσμο χάρτη.
- Το κουμπί «Προσθήκη στο ημερολόγιο» (.ics) δημιουργείται αυτόματα.
- **Σχόλια μέσα σε MDX** γράφονται ως `{/* σχόλιο */}`. Το `<!-- -->` προκαλεί σφάλμα.

**Αλλαγή:** επεξεργαστείτε το αρχείο. Αν αλλάξετε το όνομα αρχείου, αλλάζει και το URL.

**Αφαίρεση:** σβήστε το αρχείο. Οι παλιές εκδηλώσεις δεν χρειάζεται να σβηστούν, γιατί
εμφανίζονται αυτόματα στις «Παλαιότερες».

### 5.4 Νέα (Facebook)

Τα νέα **δεν** αποθηκεύονται στο repo. Οι Βαθμοφόροι απλώς ανεβάζουν post στη σελίδα Facebook.

- **Κατηγορία:** από τα hashtags του post, σύμφωνα με το `site.config.ts` → `newsCategories`. Δεν
  έχει σημασία αν γράφονται με κεφαλαία ή με τόνους. Post χωρίς γνωστό hashtag πάει στα «Γενικά».
- **Τίτλος:** η πρώτη γραμμή του post, χωρίς τα hashtags.
- **Νέα κατηγορία:** προσθέστε `{ slug: "latinika", label: "Ετικέτα", hashtags: ["#Hashtag"] }`
  στο `newsCategories`. Η σελίδα κατηγορίας δημιουργείται αυτόματα.
- **Χωρίς token:** χρησιμοποιείται το `content/mock/facebook-posts.json`, που έχει το ίδιο σχήμα
  με το Graph API. Μπορείτε να το επεξεργαστείτε για δοκιμές.
- **Σελιδοποίηση:** `facebook.perPage` (9 ανά σελίδα), `facebook.postsToFetch` (90 posts συνολικά).

**Πραγματικά νέα: δημιουργία token**

1. Λογαριασμός διαχειριστή της σελίδας Facebook → https://developers.facebook.com → _My Apps →
   Create App_ (τύπος _Business_).
2. Στο _Graph API Explorer_ επιλέξτε την app και ζητήστε τα permissions
   `pages_read_engagement` και `pages_show_list`. Πάρτε **User token** και μετά, από το
   `/me/accounts`, το **Page access token** της σελίδας.
3. Μετατρέψτε το σε **long-lived** με το _Access Token Debugger → Extend_. Το Page token που
   προκύπτει από long-lived User token συνήθως δεν λήγει, αλλά **ακυρώνεται** αν αλλάξει ο κωδικός
   του διαχειριστή ή αφαιρεθούν δικαιώματα.
4. Το `FB_PAGE_ID` φαίνεται στη σελίδα Facebook (_Σχετικά → Διαφάνεια σελίδας_) ή στο
   `/me/accounts`.
5. Βάλτε τα στο `.env.local` και τρέξτε `npm run build`.

Αν το token λήξει ή το API αποτύχει, το build **δεν** σταματά. Η σελίδα Νέα δείχνει μήνυμα με
σύνδεσμο στο Facebook και το σφάλμα γράφεται στο τερματικό του build. Ανανεώστε το token όπως
παραπάνω.

### 5.5 Ιστορικό αρχείο

Κάθε χρονιά είναι ένα αρχείο `content/archive/ΕΕΕΕ-ΕΕ.json`. Το όνομα πρέπει να ταιριάζει με το
πεδίο `year`, π.χ. `1985-86.json` ↔ `"year": "1985–86"`. Στο αρχείο γράφεται απλή παύλα, στο πεδίο
μεσαία παύλα (–).

**Α. Μαζική εισαγωγή από Excel / Google Sheets (συνιστάται)**

Το φύλλο έχει μία γραμμή ανά χρονιά και τις στήλες: _Χρονιά, Επιτελείο Συστήματος, Επιτελείο
Αγέλης, Επιτελείο Ομάδας, Επιτελείο Κοινότητας, Κατασκήνωση Αγέλης, Κατασκήνωση Ομάδας, Μεγάλη
Δράση Κοινότητας_. Παράδειγμα: `content/_templates/archeio-paradeigma.csv`.

1. Εξαγωγή σε CSV: Google Sheets → _Αρχείο → Λήψη → .csv_. Excel → _Αποθήκευση ως → CSV UTF-8_.
   Το απλό «CSV» του ελληνικού Excel αναγνωρίζεται επίσης.
2. Αντιγράψτε το στον φάκελο του project, π.χ. `archeio.csv`. Τα `*.csv`/`*.xlsx` στη ρίζα δεν
   μπαίνουν στο git.
3. Τρέξτε:

```bash
npm run import:archive -- archeio.csv --clean
```

| Επιλογή       | Σημασία                                                             |
| ------------- | ------------------------------------------------------------------- |
| `--clean`     | Σβήνει χρονιές που υπάρχουν στο `content/archive/` αλλά όχι στο CSV |
| `--year-ends` | Το σκέτο «1999» σημαίνει 1998–99 (εξ ορισμού σημαίνει 1999–00)      |
| `--offline`   | Χωρίς αναζήτηση συντεταγμένων, μόνο με γνωστούς τόπους              |

Κανόνες κελιών:

- **Επιτελεία:** ονόματα χωρισμένα με κόμμα ή αλλαγή γραμμής, με ρόλο σε παρένθεση:
  `Ελένη Σταμάτη (Ακέλα), Ρένα Παππά`.
- **Κατασκηνώσεις:** τόπος. Επιτρέπεται κόμμα (`Ελάτη, Τρικάλων`). Αν είναι πολλές, χωρίζονται με
  `;`.
- **Μεγάλη Δράση Κοινότητας:** στάσεις με τη σειρά, χωρισμένες με `-`, `→` ή αλλαγή γραμμής, με
  προαιρετικό τίτλο: `Ζαγόρι: Μονοδένδρι - Βίκος - Πάπιγκο`. Δύο ή περισσότερες στάσεις γίνονται
  διαδρομή στον χάρτη.

Οι **συντεταγμένες** αναζητούνται στο OpenStreetMap (Nominatim, 1 αίτημα/δευτ.) και
αποθηκεύονται στο `content/archive/_places.json`. Στο τέλος εμφανίζεται λίστα με τους τόπους που
δεν βρέθηκαν. Συμπληρώστε `lat`/`lng` στο `_places.json` με το χέρι και ξανατρέξτε. Οι
συντεταγμένες βρίσκονται με δεξί κλικ στο Google Maps ή στο openstreetmap.org. **Ελέγξτε στον
χάρτη** τους τόπους με κοινά ονόματα, όπως «Άγιος Νικόλαος».

Η σημείωση `note` μιας χρονιάς, αν τη γράψατε με το χέρι, διατηρείται σε κάθε νέα εισαγωγή. Οι
Βαθμοφόροι που έχουν προφίλ στο `leaders.json` συνδέονται αυτόματα, αν το ονοματεπώνυμο είναι
ίδιο.

**Β. Χειροκίνητα, για μία χρονιά**

Αντιγράψτε το `content/_templates/archive-year.json`. Πεδία:

- `leaders[]`: `name`, `role`, `section` (`systima`, `agelh-lykopoulon`, `omada-proskopon`,
  `koinotita-anixneuton` ή `eks`), και προαιρετικά `leaderId` (το `id` από το `leaders.json`, για
  να ανοίγει το προφίλ).
- `trips[]`: `title`, `section`, `type` (`point` = πινέζα, `route` = διαδρομή), `places[]` με
  `name`, `lat`, `lng`, και προαιρετικά `date` (`ΕΕΕΕ-ΜΜ-ΗΗ`).
- `note`: προαιρετικό σημείωμα για τη χρονιά.

**Αφαίρεση χρονιάς:** σβήστε το αρχείο της.

## 8. Ασφάλεια παιδιών και απόρρητο

Αυτοί οι κανόνες είναι **υποχρεωτικοί**:

- **Κανένα προσωπικό στοιχείο ανηλίκων:** όχι επώνυμα, σχολεία, διευθύνσεις ή τηλέφωνα παιδιών,
  ούτε στα κείμενα ούτε στα `alt`.
- **Φωτογραφίες με παιδιά μόνο με γραπτή συγκατάθεση γονέων** → `allowPublish: true`. Αν δεν είστε
  σίγουροι: `false`.
- Επώνυμα δημοσιεύονται **μόνο για ενήλικες Βαθμοφόρους** (προφίλ και ιστορικό αρχείο).
- Τα πρωτότυπα αρχεία φωτογραφιών (φάκελοι `αγελη/`, `ομαδα/` κτλ. στη ρίζα) **δεν μπαίνουν στο
  git** (`.gitignore`).
- **Περιοχή Μελών:** σε στατικό site **δεν** μπορεί να μπει κωδικός. Η σελίδα απλώς δεν
  εμφανίζεται σε μηχανές αναζήτησης. Μην ανεβάζετε εκεί συμπληρωμένα δελτία υγείας ή άλλα
  προσωπικά δεδομένα, μόνο κενά έντυπα και στοιχεία πληρωμής.
- Χωρίς scripts παρακολούθησης. Αν χρειαστούν στατιστικά, μόνο cookieless υπηρεσία (Plausible,
  Umami) πίσω από το `analytics.enabled` του config, και ενημέρωση της πολιτικής απορρήτου.
- Μυστικά (tokens, κλειδιά) **μόνο** στο `.env.local`, ποτέ στον κώδικα ή στο git.

## 10. Δημοσίευση

### Α. Οποιοσδήποτε στατικός hosting (τρέχουσα ρύθμιση)

Μετά το `npm run build`, ανεβάστε **όλο το περιεχόμενο του φακέλου `out/`**:

- **Netlify / Cloudflare Pages:** σύρετε τον φάκελο `out/` στο dashboard, ή συνδέστε το repo με
  build command `npm run build` και publish directory `out`.
- **GitHub Pages:** ανεβάστε το `out/` (π.χ. με GitHub Action). Αν το site είναι σε υποφάκελο
  (`/repo-name/`), χρειάζεται `basePath` στο `next.config.ts`.
- **Δικός σας server (Apache/Nginx):** αντιγράψτε το `out/` στον φάκελο του site. Οι σελίδες είναι
  `φάκελος/index.html` (`trailingSlash: true`), οπότε δουλεύουν χωρίς ειδικές ρυθμίσεις.
  Ρυθμίστε τη σελίδα σφάλματος σε `/404.html`.

Θυμηθείτε: το site είναι «φωτογραφία» της στιγμής του build. Για νέα από το Facebook ή για
ενημέρωση εκδηλώσεων χρειάζεται νέο build. Στα Netlify/Cloudflare αυτό μπορεί να γίνεται
αυτόματα, π.χ. κάθε μέρα, με ένα _build hook_ που καλείται από προγραμματισμένη εργασία (GitHub
Actions, cron).

### Β. Vercel (με server), όταν χρειαστεί

Για ωριαία ανανέωση νέων χωρίς χειροκίνητο build ή για φόρμα επικοινωνίας που στέλνει email από
τον server:

1. Στο `next.config.ts` αφαιρέστε το `output: "export"` και το `images.unoptimized`.
2. Η αποστολή email της φόρμας γίνεται με Server Action και πάροχο email (π.χ. Resend).
   Χρειάζεται υλοποίηση: σήμερα η φόρμα ανοίγει το πρόγραμμα email του επισκέπτη.
3. Ορίστε τα `FB_PAGE_ID` / `FB_PAGE_ACCESS_TOKEN` στα _Environment Variables_ του Vercel.

Πριν από αυτή την αλλαγή διαβάστε το `node_modules/next/dist/docs/01-app/02-guides/` για caching
και ISR στη συγκεκριμένη έκδοση.

### Πριν από την πρώτη δημόσια έκδοση

- [ ] Πραγματικό domain στο `site.config.ts` → `url`
- [ ] Όλα τα `TODO` έχουν συμπληρωθεί (§5.9)
- [ ] Συγκατάθεση γονέων για κάθε φωτογραφία με `allowPublish: true`
- [ ] Πραγματικό Δελτίο Υγείας και IBAN
- [ ] Πολιτική απορρήτου ελεγμένη
- [ ] Token Facebook ρυθμισμένο

## 12. Αντιμετώπιση προβλημάτων

| Πρόβλημα                                              | Λύση                                                                                                                         |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `Μη έγκυρο περιεχόμενο στο content/…`                 | Το μήνυμα δείχνει αρχείο και πεδίο (§4.2). Συνήθως λείπει `alt`/`allowPublish`, υπάρχει λάθος εσοχή στο YAML ή άγνωστο πεδίο |
| Σφάλμα YAML στο MDX                                   | Το frontmatter θέλει **κενά, όχι tabs**. Κείμενα με `:` μπαίνουν σε εισαγωγικά                                               |
| Σφάλμα «Could not parse expression» σε MDX            | Κάποιο `{` ή `<` στο κείμενο, ή σχόλιο `<!-- -->`. Χρησιμοποιήστε `{/* */}`                                                  |
| `άγνωστο leaderId`                                    | Το `leaderId` στο αρχείο δεν υπάρχει στο `leaders.json` (§5.6)                                                               |
| `EADDRINUSE` / η θύρα χρησιμοποιείται                 | Άλλος server τρέχει ήδη. Κλείστε τον (Ctrl+C) ή αλλάξτε θύρα (§2.4)                                                          |
| Το build αποτυγχάνει στις γραμματοσειρές              | Χρειάζεται internet για το Google Fonts. Ελέγξτε τη σύνδεση ή τον proxy                                                      |
| Δεν φαίνεται μια αλλαγή περιεχομένου στο `dev`        | Ανανεώστε τη σελίδα. Αν πάλι όχι, σταματήστε τον server, σβήστε τον φάκελο `.next` και ξαναξεκινήστε                         |
| Δεν φαίνεται αλλαγή στο `preview`                     | Το preview δείχνει το τελευταίο build: τρέξτε `npm run build`                                                                |
| Windows: `EPERM` / «αρχείο σε χρήση»                  | Κλείστε προγράμματα που έχουν ανοιχτό το αρχείο (προβολή εικόνων, Excel) ή τον dev server, και ξαναδοκιμάστε                 |
| Windows: «running scripts is disabled» στο PowerShell | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, ή χρησιμοποιήστε cmd/Git Bash                                         |
| Linux: `EACCES` στο `npm install`                     | Μην χρησιμοποιείτε `sudo npm`. Εγκαταστήστε το Node με nvm (§2.1)                                                            |
| Τα νέα δείχνουν «Δεν μπορέσαμε να φορτώσουμε…»        | Το token Facebook έληξε ή είναι λάθος. Δείτε το μήνυμα στο τερματικό του build και §5.4                                      |
| Εισαγωγή CSV: ελληνικά «κουκιά»                       | Αποθηκεύστε ως **CSV UTF-8**                                                                                                 |
| Εισαγωγή CSV: «Δεν βρέθηκε στήλη χρονιάς»             | Η πρώτη γραμμή πρέπει να είναι οι επικεφαλίδες, με στήλη «Χρονιά»                                                            |
| Ο χάρτης δεν εμφανίζεται                              | Χρειάζεται internet για τα πλακίδια OpenStreetMap, και πρέπει να πατηθεί «Εμφάνιση χάρτη»                                    |
| `npm install` πολύ αργό ή σφάλματα δικτύου            | Ξαναδοκιμάστε. Σε εταιρικό δίκτυο ρυθμίστε `npm config set proxy …`                                                          |
